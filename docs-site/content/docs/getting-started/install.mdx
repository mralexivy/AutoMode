---
title: "Install AutoMode"
description: "Install the AutoMode mod for Claude Code in about a minute: ask Claude, type two chat commands, or run one terminal line. Needs Claude Code 2.1.287+."
---

AutoMode installs from its own plugin marketplace. Pick one of three ways. Each takes about a minute.

<Tabs items={['Ask Claude', 'Two chat commands', 'One terminal line']}>
  <Tab value="Ask Claude">
    The easiest way. Paste this into Claude Code and press Enter:

    ```text
    Install the AutoMode plugin for me: run `claude plugin marketplace add mralexivy/AutoMode` and then `claude plugin install automode@automode`. When both succeed, tell me to run /reload-plugins.
    ```
  </Tab>
  <Tab value="Two chat commands">
    Type these in the Claude Code chat box, one at a time:

    ```text
    /plugin marketplace add mralexivy/AutoMode
    ```

    ```text
    /plugin install automode@automode
    ```
  </Tab>
  <Tab value="One terminal line">
    ```bash
    claude plugin marketplace add mralexivy/AutoMode; claude plugin install automode@automode
    ```
  </Tab>
</Tabs>

Then run `/reload-plugins`, or restart Claude Code.

## Check that it loaded

<Steps>
  <Step>
    ### Open the plugin list

    Run `/plugin`. A line under the tabs reads `1 mod active · automode`.
  </Step>
  <Step>
    ### Run the setup checklist

    Run `/automode setup`. It checks that the mod loaded, that the router is on, the activation, the routing mode and the bar. It ends with the one next step.
  </Step>
  <Step>
    ### Send a prompt

    Ask a quick question. The bar above the prompt shows the route, such as **Low · Haiku**. See [What the bar shows](/concepts/the-bar).
  </Step>
</Steps>

## Requirements

- **Claude Code 2.1.287 or later** in the terminal. Mods are on by default from that version. Tested with Claude Code 2.1.318.
- **The Desktop app** needs 2.1.286 or later. **The VS Code extension** needs 2.1.299 or later.
- **A Claude login.** A Pro, Max, Team or Enterprise plan, or an API key. AutoMode needs no key of its own.

If you set `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` in an early build, remove it. Claude Code 2.1.287 and later ignores it.

<Callout type="info" title="If the mod does not load">
  Claude Code runs as usual and nothing breaks. See [Troubleshooting](/troubleshooting).
</Callout>

## It starts on its own

There is nothing to turn on. AutoMode starts with every session after you install it and run `/reload-plugins`. It routes on whatever model the session uses, so you do not pick a special model.

<Accordions>
  <Accordion title="Why no special model?">
    AutoMode used to start only when the model ID ended in `[1m]`. Claude Code 2.1.311 removes that suffix before a mod sees the model, so the rule never fired. The old rule is still there as `"activation": "picker"` in `config.json`, for builds that keep the suffix.
  </Accordion>
  <Accordion title="Does it work on Bedrock, Vertex or a gateway?">
    The mod loads, but routing only records what it would do. AutoMode verified its cache behavior on the Anthropic API and Claude plans only. On Vertex, Bedrock, Foundry or a custom `ANTHROPIC_BASE_URL`, the router runs in shadow mode unless you set `"allowUnverifiedProviders": true` in `config.json`.
  </Accordion>
  <Accordion title="Where does it keep its state?">
    In `~/.claude/plugins/data/automode/`. See [Privacy](/security/privacy) for each file and how long it stays.
  </Accordion>
</Accordions>
