Hi HN, I'm the author. AutoMode is an open source (MIT) mod for Claude Code. It chooses the model and the reasoning effort for every prompt, so you stop switching /model and /effort by hand.

How it decides: two small Haiku judges read each prompt and estimate how hard it is and what it needs. AutoMode then picks the cheapest model and effort that can still do it. A quick question runs on Haiku at low effort, an edit on Sonnet, design work on Opus. A risk floor written in code (auth, migrations, data deletion) can't be lowered by the judges, and risky changes always get an independent review.

A few things that turned out to matter:

- Each model has its own prompt cache, so switching models mid-chat rewrites the whole conversation into the new cache. AutoMode prices that rewrite before any switch and holds the current model when the switch wouldn't pay back. Effort can still change per prompt while the model holds.
- A bar above the prompt shows the model, effort, context used, the cache countdown and the reason for each route. `/automode details` prints every decision.
- For big jobs, `am:run <task>` runs a plan, build, verify and review workflow with specialized subagents: Haiku explorers, an Opus architect, Sonnet implementers that each own their files, a verifier where exit codes decide, and an Opus reviewer.

Does it save money? On 5 mixed sessions (questions and coding in one conversation, every step graded by hidden tests), it cost $2.01, against $2.14 on Sonnet high, $3.87 with effortless and $4.14 on plain Opus. All four passed 20/20. On long coding tasks with no questions it costs about what Sonnet high costs, so it won't help much there. The first version of the benchmark actually lost to Opus; both runs, the rows and the reproduce command are public: https://mralexivy.github.io/AutoMode/docs/benchmarks/results/

It runs on your own Claude login: no API key, no proxy, no server. Happy to answer questions about the routing, the cache math or where it falls short.
