How AutoMode picks a model and effort

By Alex Ivy, who makes AutoMode. Updated October 31, 2026.

AutoMode chooses the cheapest model and effort that are still adequate for each prompt. Two Haiku judges read the prompt, code sets a quality floor for risky work, and a cost check decides whether a switch is worth it. The judge can never lower a floor. The decision takes about a second.

How a route is decided

  1. Judges give evidence. Two Haiku judges assess the prompt. A failed judge never blocks your prompt.
  2. Code sets a floor. Rules check for risk, such as security work or a migration. No model sets this floor.
  3. The optimizer picks a candidate. It takes the cheapest eligible pair of model and effort.
  4. Authority resolves the route. A user override or workflow role is final. The floor then lifts the candidate. The switch check holds or switches on cache cost, and a hold never drops below the floor.

What counts as risky work?

Code sets a risk band from S0 to S3, using the task text, the file paths, the module count and the unknowns. The band only goes up. A prompt reaches S3 if it matches security or credentials, migrations or destructive operations, concurrency, external contracts, or payments and sensitive data. S3 work always gets an Opus review.

What happens to each prompt

  • Chat and non-code requests get a direct answer.
  • Code changes with a clear goal: Sonnet does them, and must show a passing test or build before it says done.
  • High-risk changes: after the checks pass, one Opus reviewer checks the diff.
  • Open-ended work runs through the workflow below.

The workflow for big jobs

StageWhat runs
Risk bandCode, not a model. The band only goes up
DiscoverHaiku. One agent for S1, three for S2 and S3
PlanOpus. Workstreams, acceptance criteria and risks
BuildSonnet. Workstreams that share files never run together
VerifySonnet runs the commands. Code decides pass or fail from exit codes
ReviewOpus reads the diff. Mandatory for S2, S3, failed checks and unfinished work

How do I override a route?

Start a prompt with am: to steer that one prompt. For example, use am:opus, am:sonnet, am:haiku, or am:low to am:max. Your override is final. Use /automode off to stop routing for a session, and /automode on to start it again.

Where does it run?

Routing runs in the terminal, the Code tab of the Desktop app, the VS Code extension, claude -p and the Agent SDK. The bar above the prompt appears in the terminal and the Desktop app. In VS Code, use /automode for the same facts. AutoMode does not run in a WSL session of the Desktop app.

How well does it work?

The judge picked an accepted effort on 74 of 75 labeled cases. This measures the label, not cost. AutoMode has no published cost result yet, so we quote no saving. See how other routers compare.

Install AutoMode

Paste these into Claude Code, one at a time, then run /reload-plugins.

/plugin marketplace add mralexivy/AutoMode
/plugin install automode@automode

It is free. It needs no key and no server, and it starts on its own.
