# Canary results: completion gate and Sonnet executor

Date: 2026-11-01. Costs are API list-price equivalents, not plan charges. Rows: `canaries.jsonl`. Rules: `bench/experiments/CANARIES.md`, committed before the first row. Total: $16.24 over 18 runs.

**These are probes. They count toward no claim and make no saving claim.** The tasks were picked to stress each change, and the baselines ran on other days. No veto fired.

## Executor canary

`executor-sonnet`, 3 repeats each. All runs ended `done`.

| Task | Passed | Average cost | Sonnet high baseline |
|---|---:|---:|---:|
| `marked` | 3/3 | $0.16 | 3/3, $0.17 |
| `tomli` | 3/3 | $0.20 | 3/3, $0.21 |
| `dnspython` | 3/3 | $0.58 | 3/3, $0.41 |
| `ejs` | 3/3 | $0.42 | 3/3, $0.27 |
| `toughcookie` | 3/3 | $0.45 | 2/2, $0.21 |

No task fell below its baseline, so this does not veto `executor: sonnet`. It does not show the executor is cheaper. It cost more than Sonnet high on three tasks here.

Baselines come from Stage C, and for `toughcookie` from the screen. The main session ran only on Sonnet in every run, including the four tasks here that the old router sent to Opus. `toughcookie` ran at high, as its critical text requires. Its Opus requests came from the required reviewer, which accounts for part of its cost.

Nearly all runs ran at high, because the effort judge asked for it. So this tested little of the medium default.

## Gate canary

`gate-block` on `sqlglot`, 3 repeats. The route chose Opus in all three.

| Arm | Passed | Average cost |
|---|---:|---:|
| AutoMode with the gate blocking | 2/3 | $3.61 |
| AutoMode routed, no gate (`hard-probe`) | 1/5 | $3.27 |
| Fixed Opus medium (screen) | 3/3 | $3.16 |

The rejected run failed `test_set_operation_precedence`, the same test as before, and ended `done`. So the gate did not stop every false done.

2 of 3 is encouraging only. The difference from 1 of 5 is not significant (Fisher exact, two-sided p about 0.46). Rows do not record gate records, so they do not show how often the gate blocked or what it caught. The next canary must keep those records. Run 3 also escalated once.

## What this allows

Both features stay off by default. `completionGate` stays `report`, and `executor` stays `judge`. A default change needs new tasks with real outcome data, a gate overhead run, and gate records in the rows.
